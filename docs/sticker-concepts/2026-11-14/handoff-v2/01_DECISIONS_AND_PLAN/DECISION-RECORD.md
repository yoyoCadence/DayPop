# 決策紀錄｜DP-244（C 方案 Phase 1 正式核准；素材尚未驗收）

## 問題與原則

DayPop 現有 DP-243 的 **240 個系統 emoji** 已解決「選項數量」。圖檔貼圖的核心價值只有兩項：跨裝置視覺一致與 DayPop 專屬品牌風格。不能拿貼圖替代 emoji 現有功能，也不能用美術改善當理由擅自增加效能、維護或授權風險。

## 四個選擇

| 選項 | 理由／成本 | 決策 |
|---|---|---|
| A 保留原生 emoji | 零新增素材、跨裝置呈現不同 | **保留作為既有功能與永久 fallback** |
| B 採用開源 emoji 圖檔 | 風格跨裝置一致但缺少 DayPop 專屬特色；需維護署名 | 可做替代方案，不優先 |
| C 原創漫畫貼圖 | 最有品牌辨識度，製作與工程維護成本也最高 | **本次僅驗證 4 張；通過後評估 24 張** |
| D 以開源圖形為構圖參考再創作 | 可能提高一致性，但真正改作仍受原始授權拘束 | 僅研究選項，不是默許混用第三方 SVG |

**狀態：正式採 C 作為設計方向，但目前 4 張視覺稿未過 Gate；Phase 2 僅在 4 張通過後條件式啟動，Phase 3 與部署沒有自動核准。見 00_START_HERE/OWNER-DECISIONS-2026-11-14.md。**

## 已定方向

1. 漫畫／貼紙風：深色粗墨線、平塗、3–4 個主色、白色外圈，不放文字數字；避免對既有 IP 或在世畫家風格做直接模仿。
2. 1:1、透明底、主體約 88% 畫布；以 **實際 16 CSS px** 認得出為主要門檻、10px 至少看得出輪廓；必測 `#FFFFFF` / `#111111` 背景。
3. 優先提供純向量 SVG，禁止 script、字型、外部引用與嵌入點陣。PNG 只當原始輸入備選，**不在未通過尺寸審查時直接上線**。
4. 部署輸出硬上限 **每張 ≤ 4 KB**、第一批 24 張總計 **≤ 96 KB**，不得進入 JS bundle；4 張只是試作。
5. 後續最常用 24 張需依 DP-243 使用分布或產品判斷確定，**不是現在選定全部 24 張**。
6. 新資料同時有 `assetKey` 和 fallback `glyph`。SVG 無法取得時回退 emoji；既有只有 glyph 的資料永遠有效。
7. 現有提案指出 `stickers` 表已有 `asset_key`，`glyph`／`asset_key` 至少一個非空，故**原規劃不需要 DB migration**；要以最新 repo/schema 實查為準。

## 為何不一次擴充 240

使用者認得圖示、使用頻率與實際手機畫面表現，比素材數量更重要；一次做 240 張會讓風格 QA、相似性審查、版本維護與壓縮測試膨脹十倍，卻沒有充分證據證明使用者會受益。

## 品牌系統延伸（非本次範圍）

這四張可作為 DayPop 未來寵物、成就徽章、App icon 的共同設計語言研究參考，**不要將這些額外功能混入 DP-244 範圍或當成本次完成條件**。
