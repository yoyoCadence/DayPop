## 規則

1. 單一 emoji，fully qualified：預設是文字樣式的要帶 U+FE0F（`☀️` 而不是 `☀`）。
2. 不用 ZWJ 組合（👨‍👩‍👧）、膚色、國旗、keycap（1️⃣）：舊系統會拆成好幾個字。
3. **Emoji 12.0（2019）以前**。大約對應 iOS 13.2、Android 10、Windows 10 1903；更新的在 Windows 10 與舊手機會是空框。🧋（Emoji 13.0）、🪙（13.0）、🪴（13.0）因此不在清單。
4. 每個 emoji 只放一類。
5. 分類標籤兩個字，讓分類列在 360px 以上維持兩行。

`stickerGlyphs.test.ts` 把關 1、2、4、5 與原稿保留；**第 3 條測試無法離線判斷**，新增 emoji 時要照下面的方法重新核對。

## 核對方法與結果

2026-11-14 在雲端容器以 Python 套件 [`emoji`](https://pypi.org/project/emoji/) 2.16.0 的 `EMOJI_DATA`（Unicode emoji 資料，含每個 emoji 的狀態與 Emoji 版本）核對，套件只裝在暫存的虛擬環境，沒有進 repo：

```python
import emoji
for glyph in all_glyphs:
    data = emoji.EMOJI_DATA[glyph]                       # 不在表內即非 emoji
    assert data['status'] == emoji.STATUS['fully_qualified']
    assert float(data['E']) <= 12.0
```

結果：240 個都是 fully qualified，最新的是 Emoji 12.0（🟠🟡🟢🟣🥱🤍🩺🩸🩹），沒有重複，原稿 63 個 63 個都在。

## 已知限制

- 系統 emoji 的樣子由各平台決定，同一個貼圖在 iPhone、Android、Windows 看起來不一樣，也不會跟著 App 的主題變。要統一外觀需要圖檔貼圖，見 [素材規格](sticker-asset-spec.md)。
- 中文螢幕閱讀器念的是系統給的 emoji 名稱，按鈕標籤是「加入貼圖 🍜」；沒有另外翻譯 240 個名稱。
- 沒有在真機上逐一看過 240 個的顯示；相容性依據是上面的版本資料。
