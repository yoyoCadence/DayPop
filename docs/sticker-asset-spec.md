# 圖檔貼圖素材規格（提案，未定案；DP-244）

> 這份是給專案擁有者找素材用的規格。**目前的貼圖（DP-243，240 個系統 emoji）不需要任何素材**；這裡描述的是「要不要做 DayPop 自己的圖檔貼圖」以及要做的話素材要長什麼樣子。還沒有任何程式接上圖檔貼圖。

## 1. 先決定要不要做

圖檔貼圖只解決兩件事：**各裝置長得一樣**、**有 DayPop 自己的風格**。它不會讓貼圖變多，數量問題 DP-243 已經用 emoji 解決。

| 選項 | 解決什麼 | 代價 | 需要你找素材？ |
| --- | --- | --- | --- |
| A. 維持系統 emoji（現況） | — | iPhone／Android／Windows 長得不一樣，不跟主題 | 否 |
| B. 開源 emoji 圖檔集 | 各裝置一致 | 風格是通用 emoji，不是漫畫；要加署名 | 否，我直接接 |
| C. 自訂漫畫風貼紙 | 一致＋自己的風格 | 最貴：要一整套同風格素材、授權紀錄、工程接線 | **是** |

開源 emoji 圖檔集的候選（**授權請在採用時再核對原文**）：Microsoft Fluent Emoji（MIT）、Twemoji 圖檔（CC BY 4.0，需署名）、Noto Emoji（Apache 2.0／OFL）。OpenMoji 是 CC BY-SA 4.0，有「相同方式分享」的條件，不建議。

**建議**：先用 DP-243 的 emoji 一到兩週，看「最近」裡實際常用哪些。如果在意的是「在電腦上看起來不一樣」→ 選 B；如果要的是 DayPop 的品牌感 → 選 C，**而且只先做最常用的 24 張**，不要一次找 240 張。

以下第 2–7 節只適用於選項 C。

## 2. 最重要的一條：授權

素材會放進 repo，並且由網站直接提供給每個打開 App 的人下載——**這在法律上就是再散布**。很多「免費」圖庫允許你用在作品裡，但禁止把原始檔再散布，那種不能用。

可以：

- 你自己畫的，或委託畫師畫、並有書面同意「可修改、可公開散布、可商用」。
- CC0／公眾領域。
- CC BY 4.0（我們會在 App「關於」與 repo 的授權檔加署名）。
- MIT、Apache 2.0、SIL OFL 這類軟體授權的圖示集。
- 你自己用 AI 工具生成、該工具的條款允許商用，而且不模仿特定在世畫家或既有角色。

不行：

- 「僅限個人使用」「不得再散布」「需保持會員才可使用」。
- 來源不明、找不到授權頁的圖（包括 Pinterest、Google 圖片搜尋結果）。
- 含既有角色、品牌、商標、真人肖像、國旗。
- CC BY-NC（非商業）與 CC BY-SA（相同方式分享）：前者限制未來用途，後者會牽動整個專案的授權。

**每一張都要能填完第 6 節 manifest 的授權欄位**，填不出來的就不收。

## 3. 風格

- **一整套出自同一位作者或同一個素材包**。從不同地方各撿幾張，混在一起會比系統 emoji 更雜亂。
- 方向：配合 App 預設的「漫畫」主題——黑色墨線外框、平塗、最多 3–4 個主色、可少量網點；不要漸層寫實、不要照片。
- **不含文字或數字**：縮小後看不清，也無法翻譯。
- 外框外再一圈白色描邊（像剪下來的貼紙），這樣在淺色（#ffffff）與深色（#111111）背景上都看得到。

## 4. 尺寸與可讀性

貼圖在 App 裡顯示的大小（CSS px）：

| 位置 | 大小 |
| --- | --- |
| 月格（一天 1／2／3／4 張以上） | 19／15／12／10 px |
| 日詳情的貼圖列 | 20 px |
| 選擇器 | 22 px |
| 綜覽 | 23 px |

手機螢幕約 3 倍像素密度，所以最大實際約 70×70 像素。

- **畫布 1:1 正方形、透明背景**。
- **主體佔畫布中央約 88%**（每邊留約 6% 透明），貼圖之間才不會黏在一起。
- **縮到 16 px 仍要認得出是什麼**：輪廓簡單、線條粗（在 96 px 畫布上外框至少 4 px）、不要細小的裝飾。月格最小 10 px，那個大小只要求認得出輪廓和主色。

## 5. 檔案格式與大小

交給我任一種：

- **SVG**（最好）：純向量路徑，不含嵌入圖片、字型、`<script>`、外部連結。
- **PNG**：至少 512×512，透明背景。

我會統一轉成 App 用的檔案並檢查：**每張 ≤ 4 KB，第一批 24 張合計 ≤ 96 KB**，不進 JavaScript bundle（DP-243 之後 JS gzip 只剩約 1.3 KB 餘裕）。超過的請換更簡單的版本，不會放寬上限。

## 6. 交付方式

一個資料夾，內含圖檔與一份 `manifest.csv`：

```csv
id,name,category,fallback,file,author,source_url,license,license_url,modified
cake,生日蛋糕,celebrate,🎂,cake.svg,王小明,https://example.com/pack,CC BY 4.0,https://creativecommons.org/licenses/by/4.0/,改成黑框
red-envelope,紅包,celebrate,🧧,red-envelope.svg,自己畫,,owner-original,,
```

| 欄位 | 說明 |
| --- | --- |
| `id` | 小寫英文與連字號，**一經使用不能改名**（會存在每一筆貼圖資料裡） |
| `name` | 中文名稱，給螢幕閱讀器念 |
| `category` | DP-243 的分類 id：`mark` `mood` `celebrate` `work` `money` `health` `travel` `food` `home` `fun` `weather` |
| `fallback` | 對應的 emoji（必須在 [貼圖清單](sticker-catalog.md) 裡）；舊版 App 與找不到圖時顯示它 |
| `file` | 圖檔檔名 |
| `author`／`source_url`／`license`／`license_url` | 授權紀錄；自己畫的 `license` 填 `owner-original` |
| `modified` | 有沒有改過原圖、改了什麼 |

另外附上每個來源的授權頁截圖或原文（一個素材包一份即可）。

## 7. 我這邊要做的工程（收到素材後）

不需要資料庫 migration：`stickers` 表本來就有 `asset_key` 欄位，約束是 `glyph` 與 `asset_key` 至少一個不為空。

1. 新貼圖**同時存 `assetKey` 與 fallback emoji 的 `glyph`**：舊版 App、備份檔、其他裝置找不到圖時仍顯示 emoji，不會出現空白。
2. 圖檔 registry 與建置檢查（每張與總量上限、manifest 授權欄位齊全、`fallback` 在清單內）。
3. 月格、日詳情、選擇器、綜覽四處改為「有 `assetKey` 且認得就畫圖，否則畫 `glyph`」。
4. service worker 快取，離線時月格仍看得到貼圖。
5. App「關於」與 repo 加上署名與授權檔。
6. 對照板：每張在 10／16／22 px、淺色與深色背景上的樣子，給你目視驗收後才發布。

## 8. 驗收標準

- 第 2 節：每張都有可查的授權紀錄。
- 第 4 節：對照板上 16 px 認得出，10 px 認得出輪廓。
- 淺色、深色背景都看得到邊緣。
- 第 5 節的大小上限。
- 你在手機上目視確認風格一致。
